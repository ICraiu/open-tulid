## Requirements to review against

The desired feature is liveness-only worker observability:

1. A distinct worker-observability module belongs under Tulid's executor/runtime layer.
2. The executor owns the worker process/container, observation registration, failure handling, workspace cleanup, and lease release.
3. The scheduler only selects runnable tasks and starts jobs; it does not inspect worker logs or decide whether OpenCode is in a doom loop.
4. Observability periodically checks actual current worker/container liveness at a bounded configurable interval, about once per minute in production and short intervals in tests.
5. Do not parse OpenCode logs or classify `doom_loop`, `Unauthorized`, crashes, or other textual errors. All unexpected worker exits are equivalent for this feature.
6. Normal accepted completion/process termination must not be treated as a worker fault. Completion currently being validated must be handled safely.
7. An unexpected exit with no accepted completion must atomically:
   - mark the job failed/orphaned;
   - preserve structured basic exit information if available;
   - clean/scrub that job workspace idempotently;
   - release the worker/job lease;
   - leave the Kanban task in its existing state (especially Todo);
   - allow the scheduler to start a fresh attempt of the same task.
8. No arbitrary cooldown should be introduced.
9. No per-task contract generation should be reintroduced. The project global contract remains command-only.
10. Supervision must be keyed by job_id plus attempt identity, not task ID alone.
11. Immediate exits must be observable; duplicate notifications must be harmless; stale jobs/processes must not affect a current attempt.
12. The worker log files may remain useful diagnostics, but logs are not the health signal and must not be parsed to trigger failure.
13. The executor must be the only component that kills workers and cleans workspaces. Observability emits a fault/event/callback; executor performs termination and cleanup.
14. Tests must prove the real executor/observability/scheduler path, not only isolated helper behavior.
