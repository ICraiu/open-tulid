Problem:
Workers run OpenCode inside Docker. Tulid currently sees only a nonzero return code, while the real cause is in `.open-tulid/logs/agent.log` and/or stderr. Example task #8:
- OpenCode configuration contains `permission: {"*": "allow", "doom_loop": "deny"}`.
- OpenCode repeatedly edited/generated fixture hashes.
- OpenCode then emitted `Error: Unauthorized: unauthorized` and exited code 1 because its doom-loop safety denied the next operation.
- Tulid recorded only `returncode=1`, hiding the actionable cause.

Design requirement:
The scheduler must not guess. The executor must classify the completed worker result immediately after process exit, before generic returncode handling:

Docker process exits
→ executor reads stdout, stderr, agent.log
→ deterministic OpenCode error classifier examines captured evidence
→ structured failure code/category/retryability/evidence is stored in job metadata/events
→ scheduler receives that structured result and applies bounded retry policy

Add typed structured classification, for example:
- `opencode.doom_loop`: OpenCode denied a repetitive tool operation; retryable with a fresh attempt/context.
- `opencode.tool_unauthorized`: OpenCode/tool permission denial not specifically doom_loop; retryability explicit/limited.
- `opencode.context_limit`: context-window exhaustion; retryable only with a shortened prompt/context.
- `opencode.model_error`: provider/API/model failure; retryable.
- `opencode.timeout`: worker timeout; retryable according to existing policy.
- `opencode.unknown_failure`: nonzero OpenCode exit without a recognized signature.
