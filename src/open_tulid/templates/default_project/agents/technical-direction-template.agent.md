# Technical Direction Template

Use this structure for `technical-direction.md`:

1. Decision needed
2. Observed repository and product context
3. Goals and non-goals
4. Assumptions
5. Options exploration
6. Recommendation
7. Architecture, module ownership, and composition root
8. Runtime, package, build, and library decisions
9. Public compatibility, errors, and exit conventions
10. External boundaries and deterministic test strategy
11. Project invariant commands and expected observations
12. Migration or compatibility plan
13. Decision ledger: decided, deliberately deferred, and owner
14. Open questions, each labeled informational or implementation-blocking
