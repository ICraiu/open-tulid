# Implementation Specification Template

Use this structure for `implementation-spec.md`:

1. Purpose
2. Scope
3. Observed repository inventory and relevant manifests
4. Functional behavior
5. Module ownership table with exact repository paths
6. Public symbols, signatures, and behavioral contracts
7. Data model and persistence
8. Runtime flows
9. Failure behavior, errors, exits, and fallback rules
10. Security and privacy considerations
11. Dependency and integration seams
12. Focused checks and project invariants with exact commands and observations
13. Decisions every child execution contract must preserve
14. Rollout or migration plan
15. Acceptance criteria mapped to checks or invariants
16. Implementation-blocking decision status
17. Informational open questions
